## 2. 프로젝트 개요

  * **건강정보 등록**: 신규 레코드 추가 (UI로 추가, 엑셀로 추가, 중복 체크), 환자식별번호 생성
  * **건강정보 조회/검색 (목록, 개인)**: 목록 보기, 상세 검색하기
  * **건강정보 수정**: 등록된 사람의 건강정보 수정하기
  * **건강정보 삭제**: 등록된 건강정보 삭제하기
  * **건강정보 통계**: 정보의 수, 평균 등 유용한 통계정보 산출
* **기술적 내용**
  * **파일**: 파일 1~2개로 건강정보를 저장하고 불러오기
  * **로직**: 건강정보 CRUD (Create, Retrieve, Update, Delete), BMI 구하기, 통계 구하기

## 4. 요구사항 명세

### 4.1 기능 요구사항 (Functional Requirements)

* **FR-01. 건강정보 등록**
  * **신규 레코드 추가 (UI 입력)**: GUI 화면을 통해 사용자의 사람 정보(식별번호, 이름, 생년, 성별)와 건강 정보(키, 몸무게, 추가 건강 정보)를 직접 입력 받아 등록할 수 있어야 한다.
  * **중복 체크**: 신규 등록 시 이미 존재하는 데이터(식별번호 또는 중복된 개인 정보 등)가 있는지 검사하여 중복 등록을 방지해야 한다.
  * **환자식별번호 자동 생성**: 신규 레코드 추가 시 고유한 식별번호(ID)를 시스템 내부 로직에 의해 자동으로 발급해야 한다.
  * **(선택) 엑셀 파일 일괄 등록**: 외부 엑셀 파일(CSV 등)을 업로드하여 여러 사용자의 건강 정보를 한꺼번에 시스템에 추가할 수 있어야 한다.
* **FR-02. 건강정보 조회 및 검색 (목록, 개인)**
  * **전체 목록 보기**: 시스템에 등록된 전체 사용자들의 건강 정보 리스트를 엑셀 표(격자) 형태로 한눈에 조회할 수 있어야 한다.
  * **상세 검색하기**: 이름, 식별번호, 또는 특정 조건(BMI 상태 등)을 기반으로 원하는 사용자의 정보를 검색하여 상세히 조회할 수 있어야 한다.
* **FR-03. 건강정보 수정**
  * **개인별 정보 갱신**: 등록된 특정 사람을 선택하여 키, 몸무게, 추가 건강 정보 등 변경된 내용을 수정하고 즉시 반영할 수 있어야 한다.
  * **BMI 자동 재계산**: 수정 과정에서 키나 몸무게가 변경될 경우, 이에 연동하여 BMI 수치와 비만도 판정 결과가 자동으로 재계산되어 업데이트되어야 한다.
* **FR-04. 건강정보 삭제**
  * **레코드 제거**: 시스템에 등록된 특정 사람의 건강 정보 및 사람 정보를 안전하게 선택하여 목록 및 영구 저장소에서 삭제할 수 있어야 한다.
* **FR-05. 건강정보 통계**
  * **통계 정보 산출**: 등록된 전체 데이터의 총 정보 수(인원수), 평균 키, 평균 몸무게, 평균 BMI 수치 등 프로그램 관리 및 분석에 유용한 요약 통계 정보를 연산하여 화면에 시각화해 제공해야 한다.

### 4.2 추가 요구사항 (비기능 및 제약 사항)

1. **예외 및 오류 처리 요구사항 (Robustness & Error Handling)**
   * **입력 값 검증 (Validation)**: 사용자가 키나 체중에 문자열(글자)을 입력하거나, 음수(0 또는 0 이하)를 입력했을 때 프로그램이 비정상 종료(Crash)되지 않아야 한다. 잘못된 값이 입력된 경우, `messagebox` 등을 통해 사용자에게 올바른 숫자 입력을 유도하는 경고 메시지를 출력해야 한다.
   * **파일 입출력 예외 방어**: 파일을 읽거나 쓸 때 권한 문제, 디스크 용량 부족, 파일 손상 등의 예외 상황이 발생해도 `try-except` 구문을 통해 안전하게 처리하고 기본값(빈 리스트 등)을 반환해야 한다.
2. **사용성 및 사용자 경험(UX) 요구사항 (Usability)**
   * **직관적인 피드백**: 데이터 추가, 수정, 삭제, 파일 저장 등의 작업이 성공적으로 완료되었을 때 사용자에게 알림 팝업(`messagebox.showinfo`)을 제공해야 한다.
   * **상호작용 편의성**: 표(`Treeview`)에서 데이터를 확인하는 것에 그치지 않고, 특정 행을 클릭했을 때 입력 폼에 데이터가 자동으로 채워져 수정과 삭제를 곧바로 수행할 수 있는 편의 기능을 제공해야 한다.
3. **코드 품질 및 유지보수성 요구사항 (Maintainability & OOP Principles)**
   * **역할과 책임의 분리 (SoC, Separation of Concerns)**: 데이터 정의/파일 입출력(`health_db.py`), 핵심 알고리즘/CRUD 로직(`health_logic.py`), 화면 시각화 및 이벤트 처리(`health_gui.py`)가 상호 독립적인 모듈로 철저히 분리되어야 한다.
   * **객체지향 설계 적용**: 반복되는 데이터 구조와 연산은 클래스와 메서드로 캡슐화하여 코드의 재사용성을 높여야 한다.
   * **가독성 및 문서화**: 주요 클래스와 함수에는 목적과 인자를 설명하는 독스트링(Docstring) 및 주석을 충실히 작성해야 한다.
4. **환경 및 제약 사항 (Constraints)**
   * **파이썬 표준 라이브러리 활용**: GUI는 파이썬 기본 내장 라이브러리인 `tkinter`를 활용하며, 추가적인 외부 GUI 라이브러리 설치 없이 실행할 수 있어야 한다.
   * **동일 디렉토리 구조 유지**: 모듈 간 유기적인 `import`가 원활히 이루어질 수 있도록 모든 소스 파일은 동일한 루트 디렉토리 안에 위치해야 한다.

## 7. 건강정보 레코드 구조

| 필드명 (Key) | 데이터 타입 | 설명 (Description) | 예시 값 |
| :--- | :--- | :--- | :--- |
| `id` | String (문자열) | 고유 환자식별번호 (자동 생성) | `"P2026-0001"` |

## 8. 파일 구조 설계 및 예제

### 8.1 지원 파일 저장 형식 (4가지)

| 파일 형식 | 확장자 | 저장 구조 및 특징 | 주요 활용 목적 |
| :--- | :--- | :--- | :--- |
| **1. JSON** | `.json` | 딕셔너리 리스트 형태의 텍스트 구조<br>사람이 읽기 쉽고 웹 표준과 완벽히 호환됨 | 표준 데이터 저장 및 웹/외부 연동 |
| **2. CSV** | `.csv` | 쉼표(`,`)로 구분된 텍스트 행(Row) 구조<br>첫 행에 헤더(컬럼명) 포함 | 엑셀 일괄 등록(엑셀로 추가) 및 표 형식 관리 |
| **3. 일반 텍스트 (TXT)** | `.txt` | 커스텀 구분자(`,` 등)로 연결된 한 줄 단위 문자열<br>외부 라이브러리 없이 기본 파일 입출력으로 구현 | 가벼운 텍스트 기반 수동 로그 및 단순 저장 |
| **4. Pickle (이진)** | `.pkl` | 파이썬 객체 구조를 바이트 스트림 그대로 직렬화<br>파이썬 전용으로 복잡한 파싱 없이 통째로 저장/복원 | 프로그램 내부 객체 상태의 완벽한 보존 |

```json
    "bmi": 23.67,
    "status": "과체중"
  },
  {

    "status": "정상"
  }

```

#### 2) CSV (UTF-8, `health_data.csv`)

## 11. 팀프로젝트 AI 사용 제약사항

* **사용은 할 수 있으나, 작성된 코드에 대해 본인이 책임을 져야 함**
  * 코드에 대한 완벽한 이해를 바탕으로 구두 답변이 가능해야 함
  * 코드를 수정하라는 요구에 그 자리에서 즉각 응할 수 있어야 함
* **AI를 사용한 코드 부분에는 반드시 AI 주석 처리해야 함**
  * AI 종류
  * AI 사용 목적
  * 사용한 AI 프롬프트
  * 사용한 사람, 날짜 등
* ⚠️ **주의사항**: AI 사용 주석 처리를 하지 않은 코드는 **부정행위로 간주하여 불이익**이 부여됨
